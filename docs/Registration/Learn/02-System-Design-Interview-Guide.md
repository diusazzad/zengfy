# মডিউল ০২: সিস্টেম ডিজাইন ইন্টারভিউ গাইড (System Design Guide)

> **ইন্টারভিউ ফোকাস:** "Design a scalable, secure User Registration & Verification System for 10M users."

---

## ১. হাই-লেভেল আর্কিটেকচার ডায়াগ্রাম

```
[ ইউজার মোবাইল / ওয়েব ]
          │ HTTPS (TLS 1.3)
          ▼
   [ Cloudflare WAF ]  ───► DDoS সুরক্ষা, রেট লিমিট ও বোট ফিল্টারিং
          │
          ▼
 [ Nginx Load Balancer ]
          │
          ▼
   [ Auth API Pods ] (Stateless Microservices)
     │            │             │
     ▼            ▼             ▼
[ Redis Cache ] [ PostgreSQL ] [ Asynchronous Queue (BullMQ/RabbitMQ) ]
 (রেট লিমিট ও   (Master-Replica, │
  আইডেমপোটেন্সি)  CITEXT, UUID)  ▼
                        [ Email Worker Service ]
                                │ SMTP
                                ▼
                       [ ইউজার ইনবক্স ]
```

---

## ২. কেন ইমেইল পাঠানো কখনোই সিঙ্ক্রোনাস হওয়া যাবে না?

- **সমস্যা:** রেজিস্ট্রেশন রিকোয়েস্টের মাঝেই সরাসরি SMTP সার্ভারে কানেক্ট করলে রিকোয়েস্টে ১ থেকে ৩ সেকেন্ড সময় নষ্ট হয়। মেইল সার্ভার সাময়িক ডাউন থাকলে পুরো রেজিস্ট্রেশন এপিআই ক্র্যাশ বা টাইম-আউট হবে।
- **সমাধান:** এপিআই শুধুমাত্র ডেটাবেজে ইউজার ও টোকেন হ্যাশ সেভ করবে এবং সাথে সাথে Redis Queue-তে একটি `UserRegisteredEvent` পুশ করে ইউজারকে **`201 Created`** ফেরত দেবে (< ৫০ মিলিসেকেন্ডে)। ব্যাকগ্রাউন্ড ওয়ার্কার সেই কিউ থেকে রিট্রাই লজিক সহ ইমেইল পাঠাবে।

## ৩. স্টেট মেশিন ও লাইফসাইকেল (Finite State Machine)

```
[ PENDING_VERIFICATION ] ──(ইমেইল ক্লিক)──► [ ACTIVE ]
          │                                     │
    (২৪ ঘণ্টার মেয়াদ শেষ)                         ▼
          ▼                              [ SUSPENDED ] (স্প্যাম পলিসি)
     [ DELETED ]
```

- **ইন্টারভিউ টিপ:** ডাটাবেজে ইউজার স্ট্যাটাস হ্যান্ডেল করতে সবসময় স্ট্রিং না দিয়ে **ENUM** অথবা স্টেট মেশিন প্যাটার্ন ব্যবহার করুন।
